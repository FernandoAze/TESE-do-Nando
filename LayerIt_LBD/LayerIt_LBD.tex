\begin{abstract}
Music Information Retrieval (MIR) research frequently requires figures that overlay audio representations, symbolic scores, and algorithmic outputs in a single, time-aligned view. Yet, such visualisations are typically produced through manual, non-reproducible image editing. In this Late Breaking Demo we present LayerIt!, a composable, layer-based Python framework in which heterogeneous visual elements share a common time axis provided by ScoreWarp. Layers are combined into a single, semantically structured SVG file, preserving each visual element as an independently identifiable component while also preserving MEI data and high image resolution. We demonstrate LayerIt! through a beat-tracking case study in which four heterogeneous layers, a time-warped score, a mel spectrogram, a chromagram, and a waveform, are composed and vertically aligned by time. LayerIt! is released as an open-source, pip-installable library, offering the MIR community a reusable and extensible foundation for score-aligned visualisation workflows.
\end{abstract}

\section{Introduction}\label{sec:introduction}

MIR workflows frequently call for figures that overlay audio representations, such as waveforms, spectrograms, or chromagrams, with symbolic score notation and algorithmic outputs (e.g., beat or onset data) in a single, time-coherent view. In practice, such figures are still produced through \textit{ad hoc}, non-reproducible processes: individual visualisations are exported separately from different tools and then manually aligned and composited using image editing software. This workflow is labour-intensive and impossible to reliably reproduce or re-run on new data.

Existing tools only partially address this need. Sonic Visualiser supports audio analysis and annotation, but not composing multiple heterogeneous visualisations into a single, automatically aligned export. Piano Precision~\cite{jiangPIANOPRECISIONADVANCING2025}, a Sonic Visualiser fork, links a score to a performance through discrete anchor-based correspondences rather than a continuous time axis, a design suited to guided-listening interfaces but incompatible with producing static figures. Code-based alternatives such as Matplotlib~\cite{thematplotlibdevelopmentteamMatplotlibVisualizationPython2026}, librosa~\cite{mcfeeLibrosaLibrosa01102025}, and Modusa~\cite{modusa} offer strong individual plotting capabilities, but composing score-aligned, multi-layer figures with them still requires lengthy custom integration code, often followed by manual image editing.

This paper introduces LayerIt!, a framework that reframes this task as one of \textit{composition} rather than editing. LayerIt! represents audio, score, and algorithmic visualisations as reusable layers sharing a common time axis, and renders their composition into a single, semantically structured SVG file. The remainder of this paper describes the framework, demonstrates it with a beat-tracking case study, and concludes with directions for community-driven extensions.

\section{The LayerIt! Framework}\label{sec:framework}
At the core of LayerIt! is a simple design philosophy: every visual element, whether an audio representation, a symbolic score, or an algorithmic output, is treated as a reusable and composable \texttt{Layer} object. Each \texttt{Layer} subclass exposes a standard interface consisting of a \texttt{load\_data()} method, which ingests the raw data it needs, and a \texttt{draw()} method, which renders itself onto a shared canvas. A \texttt{Visualizer} object orchestrates a stack of such layers, coordinating them through a shared rendering context (\texttt{shared\_data}); the user only declares how layers are arranged, while the \texttt{Visualizer} handles the composition. The resulting output is a single SVG file in which each layer is preserved as a named \texttt{<g>} group element within the SVG's XML tree. Because layers are decoupled from one another behind this common interface, new layer types, backends, or rendering strategies can be added without modifying existing code.

The framework builds on established libraries rather than reimplementing their functionality: librosa~\cite{mcfeeLibrosaLibrosa01102025}, Matplotlib~\cite{thematplotlibdevelopmentteamMatplotlibVisualizationPython2026} and Modusa~\cite{modusa} handle general audio and data visualisation. BeatThis!~\cite{foscarinBeatThisAccurate2024a} supplies Beat Tracking data (used for the case study in \section{sec:demo}). Finally ScoreWarp~\cite{goeblLetsScoreWarpAgain2025a} is the time-alignment backbone of LayerIt!: beyond providing a time-warped rendering of the score itself, it establishes the continuous time axis onto which every other layer is scaled against.

LayerIt! also preserves MEI semantic metadata such as note identities, time signatures or annotations. It extends this by embedding every composed layer as its own named \texttt{<g>} group within the SVG's XML tree, maintaining this semantic hierarchy and keeping each layer independently identifiable and inspectable. In practice, this lets post-processing tools query, restyle, or animate individual layers without re-running the composition, and simplifies integration with web-based or interactive viewers, since the exported structure is already semantically rich. This bridges the gap between computational generation in Python and downstream interactive or exploratory analysis in the browser, a capability no purely raster-based export can offer.

\section{Demonstration}\label{sec:demo}
We used LayerIt! to compose a time-aligned visualisation for a beat-tracking case study, shown in Figure~\ref{fig:layerit_demo}. Four layers were composed and vertically stacked, from top to bottom: (1) the time-warped score rendered via ScoreWarp; (2) a mel spectrogram, colour-coded by energy; (3) a chromagram showing energy across the twelve pitch classes, with the BeatThis! beat activation curve overlaid; and (4) the raw waveform, with detected beats and downbeats overlaid as red and blue markers, respectively. Figure~\ref{fig:layerit_demo} was generated entirely programmatically in approximately 70 lines of Python code, with each layer defined by 5--7 lines following the same standard pattern and with no manual image editing at any stage.

The thin dotted lines represent onset markers and further illustrate the alignment. Spectral energy peaks line up with detected onsets, and chroma peaks correspond to pitches in the score. 

The beat activation curve further reveals BeatThis!'s internal confidence, which, read alongside the spectrogram and chromagram, contextualizes the detections overlaid on the waveform. Because the same script can be re-run unchanged on new recordings, scores, or algorithmic outputs, this kind of multi-layer inspection becomes reproducible rather than a one-off editing exercise, exemplifying how composing visualisations, rather than editing them after the fact, is a more suitable abstraction for MIR research.

\section{Conclusion}\label{sec:conclusion}

LayerIt! reframes multi-modal MIR visualisation from an image-editing problem, manual, \textit{ad hoc}, and non-reproducible, into a composition problem: programmatic, semantic, and extensible. Rather than aligning visual elements via \textit{ad hoc} or manual methods, researchers declare and compose layers in Python, and the resulting output is a structured SVG rather than a flattened raster image, one that preserves semantics and remains open to further analysis or modification. LayerIt! is early-stage but functional, with a stable core architecture; it is already open-source and pip-installable, and its immediate development focus is growing its library of pre-built layer types. Planned extensions include further layer types (e.g., tempograms, spectrogram derivatives), support for time-alignment backends beyond ScoreWarp, and annotation support that lets researchers export annotations alongside the visualisation. The same structured SVG output also opens the door to interactive, playback-synchronised viewers. By treating visualisation as composition rather than image editing, LayerIt! aims to make MIR research faster, more transparent, and more reproducible.
